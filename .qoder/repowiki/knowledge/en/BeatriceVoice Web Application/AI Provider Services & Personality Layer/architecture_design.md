Each file is a self-contained service module exporting pure async functions — there is no central registry or base class. `gemini.ts` and `ollama.ts` implement the same streaming chat interface (`generateChatResponseStream`) against different backends, while `flux.ts` handles image generation via Hugging Face Inference API. `beatricePersona.ts` holds the shared system prompts that both providers import as their `SYSTEM_PROMPT`. `tools.ts` defines Google `FunctionDeclaration` schemas plus an `executeTool` dispatcher used by Gemini's function-calling loop. `memory.ts` and `profile.ts` are Supabase data-access layers over `memories` and `device_profiles` tables, with `device.ts` providing a browser-persisted device fingerprint used as the user key. Dependency direction is one-way: providers depend on `beatricePersona` and optionally `tools`; persistence modules depend only on `supabase` and `device`; nothing imports from each other except through these explicit boundaries.
