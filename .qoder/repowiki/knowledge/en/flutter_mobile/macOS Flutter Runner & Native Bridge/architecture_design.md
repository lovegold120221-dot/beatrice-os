The module is a standard Flutter macOS template with three layers:
- `Runner/` — the Xcode application target. `AppDelegate.swift` extends `FlutterAppDelegate` to control app lifecycle; `MainFlutterWindow.swift` creates a `FlutterViewController`, sets it as the window's content view controller, and calls `RegisterGeneratedPlugins(registry:)` to wire up platform channels.
- `Flutter/` — Flutter tooling artifacts. `ephemeral/` holds build-time generated files (`Flutter-Generated.xcconfig`, `flutter_export_environment.sh`, `.packages`) produced by `flutter pub get`; `GeneratedPluginRegistrant.swift` is auto-generated and imports each enabled plugin (app_links, audioplayers_darwin, file_selector_macos, flutter_secure_storage_darwin, record_macos, shared_preferences_foundation, url_launcher_macos) and registers them through the Flutter plugin registry.
- `Runner.xcodeproj` / `Runner.xcworkspace` — Xcode project and workspace that link the Runner target against the FlutterMacOS framework and CocoaPods-managed plugins.
Dependency direction is one-way: Runner → GeneratedPluginRegistrant → individual plugin frameworks; nothing in the Flutter ephemeral directory depends on Runner code.
