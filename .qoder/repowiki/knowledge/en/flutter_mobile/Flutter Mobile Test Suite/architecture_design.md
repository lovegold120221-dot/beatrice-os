All test files live under `flutter/test/` and follow the standard Flutter `flutter_test` layout: each Dart file targets a single production service or feature (e.g. `audio_service.dart`, `mobile_task_coordinator.dart`, `voice_opening_service.dart`, `live_api_service.dart`) and is organized as a `void main()` block with one or more `test(...)` or `testWidgets(...)` cases. The suite uses `package:beatrice/data/services/*` imports to exercise domain logic directly, and relies on `flutter_test/flutter_test.dart` for assertions and `MockClient` from `package:http/testing.dart` for HTTP mocking. A single entrypoint `widget_test.dart` bootstraps shared test fixtures (`SharedPreferences.setMockInitialValues`, `Supabase.initialize`) in a `setUpAll` hook before running the root `BeatriceApp` widget test. There are no shared test helpers — each file is self-contained.
